# ADR 0001 — Architecture overview

Status: accepted

## Context

Fullstack take-home test: checkout for a product paid by credit card through an
external payment gateway (sandbox only). See [../PRD.md](../PRD.md) for the full
functional detail. The repo is public → never mention the payment gateway/company
name in code, repo name or commits; use generic terms instead (`PaymentGateway`,
`PAYMENT_API_URL`).

## Decisions

| Topic | Decision | Why |
|---|---|---|
| Apps | 2 apps: React frontend + Nest backend (no BFF) | A BFF doesn't add rubric points and duplicates coverage effort. The backend already isolates the gateway's private key. |
| Repo | Monorepo (no Nx/Turborepo) | A single deliverable link; boundaries designed so it can be split into separate repos later (`git filter-repo`). |
| Infra | No Kubernetes, no Lambda. Small EC2 with Docker Compose | Same compose file as local, low cost, no cold starts. |
| Frontend hosting | S3 + CloudFront | Cheap, HTTPS included. |
| HTTPS / headers | CloudFront in front of everything (`/api/*` → EC2) | HTTPS without owning a domain, no CORS, security headers via response headers policy (OWASP bonus). |
| IaC | Terraform in `/infra` | The test explicitly lists IaC as evaluated. |
| Observability | Sentry (front + back) + structured logs with pino and correlation ID | Grafana/OpenTelemetry left as a "if this had to scale" note. |
| Specs | Spec-driven: general spec + per-app spec (including infra), with TDD and TASKS where relevant | PRD → ARD → TDD → Tasks → Tests → Implementation. |

## Architecture

```
User ──HTTPS──► CloudFront ──┬── /*      → S3 (React SPA)
                              └── /api/*  → EC2 (Docker Compose)
                                             ├── Nest backend
                                             └── Postgres (internal network only)
Frontend ──(public key)──► Gateway: card tokenization
Backend ──(private key)──► Gateway: create transaction / check status
```

### EC2
- Security group only accepts traffic from CloudFront (AWS-managed prefix list).
- Postgres has no port exposed outside the Docker network.
- Secrets: Terraform generates a `random_password` → SSM Parameter Store
  (SecureString) → the deploy builds `.env` on the EC2 instance by reading SSM using
  the instance's IAM role.
- `POSTGRES_PASSWORD` only applies on the volume's first startup.
- Tables and seed data: ORM migrations + seed, not baked into the image.

### CI/CD (GitHub Actions, one workflow per app, path-filtered on `frontend/**`, `backend/**`, `infra/**`)
- On PR: tests + coverage, with a Jest `coverageThreshold` of 80% (the PR fails if not
  met).
- On push to main: build images → ECR → deploy via SSM (no SSH exposed):
  `docker compose pull && up -d`. Frontend: build → `s3 sync` → CloudFront
  invalidation.
- AWS authentication via OIDC (no access keys).

Rules to keep the option of splitting into separate repos later:
- No imports across app folders.
- The only shared artifact is the API contract (OpenAPI generated by Nest/Swagger).
- Each app runs standalone: its own `package.json`, Dockerfile, tests and env vars.

## Card data security
- The frontend tokenizes the card directly with the gateway using the public key.
  The card number and CVC never reach the backend; the backend only receives the
  token.
- The integrity signature (hash of reference + amount + currency + integrity secret)
  is generated on the backend.
- Redux persist only stores: checkout step, transaction ID, delivery data and
  product. Never the PAN or CVC.
- Pino redacts token, email and address. Sentry uses `beforeSend` to filter sensitive
  data.

## Backend: hexagonal + Railway Oriented Programming
- Library: `neverthrow` (`Result`, `ResultAsync`, `andThen`, `match`).
- Use cases chain steps that return `ok(...)` or `err(...)`; error types are
  accumulated into a union.
- Domain errors defined in the domain layer (classes with a `type` discriminant):
  `ProductNotFound`, `OutOfStock`, `PaymentDeclined`, `GatewayError`,
  `InvalidTransition`, etc.
- Output ports (interfaces) in the domain/application layer declare their errors,
  e.g.: `charge(req): ResultAsync<Payment, GatewayError | PaymentDeclined>`
- Adapters convert external exceptions (Axios, ORM) into domain errors via
  `ResultAsync.fromPromise`. Exceptions die at the boundary.
- Distinguish a technical failure (timeout/5xx → `GatewayError` → transaction ERROR)
  from a business response (card declined → `PaymentDeclined` → transaction
  DECLINED).
- The controller only translates via an exhaustive `switch` to HTTP: NotFound→404,
  OutOfStock→409, PaymentDeclined→422, GatewayError→502.

## Transaction state machine
```
PENDING → APPROVED | DECLINED | VOIDED | ERROR   (immutable final states)
```
- `transitionTo(next): Result<Transaction, InvalidTransition>` on the entity.
- Enforced at the DB level: `UPDATE ... SET status = $2 WHERE id = $1 AND status =
  'PENDING'`. If it affects 0 rows, another process already updated it → don't touch
  the stock (avoids double-decrementing between polling and a webhook).
- Stock is only decremented if APPROVED, via an atomic update (`WHERE stock > 0`).
- Payment status: polling the gateway; a webhook (with an events key and signature
  validation) as a plus.

## Frontend
- A `step` value in Redux that only moves forward in order, persisted → refreshing
  returns to the current step (the test's resiliency requirement).
- ErrorBoundary + Sentry.
